Andrej Karpathy снова сделал то, что у него получается лучше всего: сформулировал идею (на самом деле он поддержал идею Tobi Lutke), которая витала в воздухе, но которой не хватало точного названия: **Context Engineering**.

Люди обычно связывают промпт с коротким описанием задачи, которую дают AI. В то время как в приложениях с LLM под капотом происходит "Context Engineering".

Context Engineering заключается в правильном использовании контекста в запросах к LLM.  
Тут всё просто. Делайте хорошо (давайте правильный контекст), плохо не делайте (не давайте лишней информации); **Garbage In, Garbage Out**.

## Что такое контекст?

Контекст — это вся информация, которую мы передаём в запросе к LLM:
- **system prompt** — инструкции от разработчиков AI Coding tool + пользовательские правила
- **user prompt** — запрос пользователя + файлы с кодом
- **conversation** — история переписки в текущем чате
- **tools** — function calling инструменты, которые модель может вызвать
- **structured output** — json схема ответа модели

## Основные проблемы

**◾️ Отравление контекста** — модель пошла не по тому пути и сохранила ошибку в conversation.  
✅ Внимательно читать ответ модели. Если не поняла — вернуться назад, поправить промпт, отправить заново.

**◾️ Переполненность контекста** — несколько задач в одном чате → расфокус → потеря качества.  
✅ Один чат = одна задача (для 128K моделей типа Claude Sonnet). Gemini 2.5 Pro (1M) — можно давать несколько связанных задач.

**◾️ Лишняя информация** — нерелевантные файлы и документация сбивают модель.  
✅ Грамотно выбирать только нужные файлы и документацию заранее.

**◾️ Противоречия в rules** — противоречивые правила путают модель.  
✅ Постоянно обновлять rules. `/init` — хорошая база в начале, но потом всё равно нужна ручная доработка.

## Дополнительные решения

**◾️ Правильный выбор tools** — не добавлять все MCP серверы подряд, только реально нужные.

**◾️ Грамотное использование summary** — компрессия истории может терять суть задачи. Лучше открывать новый чат.

**◾️ Context Offloading** — использовать scratchpad-файлик: просим модель записывать туда информацию, потом читать её оттуда. Пример от Anthropic Best Practices: запустить линтер → сгрузить результат в файл → решать проблемы по очереди из файла.
