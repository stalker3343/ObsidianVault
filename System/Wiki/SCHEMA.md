# Wiki Schema — инструкция для LLM

Это персональная вики об Артёме, построенная по паттерну Andrej Karpathy (llm-wiki.md).
Ты — LLM. Твоя работа: писать и поддерживать эту вики. Артём читает.

---

## Три слоя

**Raw Sources** (читаешь, никогда не меняешь):
- `Daily/*.md` — ежедневные логи
- `Inbox/*.md` — статьи, видео, посты
- Всё что Артём присылает в чат

**Wiki** (`System/Wiki/`) — твоя зона ответственности:
- Ты создаёшь страницы, обновляешь их, поддерживаешь cross-references
- Артём только читает

**Schema** — этот файл. Объясняет тебе как работать.

---

## Структура вики

```
System/Wiki/
  SCHEMA.md          ← этот файл, читай первым
  index.md           ← каталог всех страниц, читай при каждом разговоре
  log.md             ← append-only лог всех операций

  entities/          ← страница на каждый важный объект
    artyom.md        ← главная страница — профиль, ценности, контекст
    anya.md
    buddy.md
    [другие люди, места, инструменты по мере появления]

  topics/            ← синтез по темам, живёт и растёт
    health.md
    productivity.md
    work-career.md
    relationships.md
    learning.md
    wedding.md
    finance.md
    [новые темы создавай сам по мере необходимости]

  insights/          ← дистиллированные паттерны и выводы
    patterns.md      ← стабильные поведенческие паттерны
    values.md        ← ценности и убеждения, как они эволюционируют
```

**Правило создания новых страниц:** если концепция упоминается на 3+ страницах — заводи отдельную страницу и ставь cross-reference.

---

## Навигация

Читай в таком порядке:
1. `index.md` — чтобы понять что есть в вики
2. Релевантные страницы по теме разговора

Не надо читать всё сразу. `index.md` скажет тебе что читать.

---

## Операции

### Ingest (обновление из источника)
Триггер: "обнови вики", "запиши в вики", или конец дня.

1. Прочитай источник (Daily, присланный текст)
2. Определи затронутые страницы — entity + topic + insights
3. Обнови каждую: **не переписывай**, дополняй и уточняй
4. Если новое противоречит старому — замени с датой: `~~старое~~ → новое (2026-05-08)`
5. Проверь cross-references — добавь ссылки если нужно
6. Обнови `updated:` в frontmatter
7. Добавь запись в `log.md`: `## [YYYY-MM-DD] ingest | источник`
8. Один `git_atomic_commit` для всех файлов

Один источник может затронуть **5–15 страниц** — это нормально.

### Query (вопрос о себе)
1. Прочитай `index.md`
2. Прочитай релевантные страницы
3. Ответь с опорой на вики
4. Если ответ содержит ценный синтез — предложи сохранить его как новую страницу вики

### Lint (раз в месяц по запросу)
Проверь:
- Противоречия между страницами
- Устаревшие утверждения (есть дата, прошло много времени)
- Страницы без входящих ссылок (orphans)
- Важные концепции без своей страницы
- Пробелы — что стоит добавить

## Форматирование страниц

Каждая страница:
```markdown
---
wiki_page: [название]
type: entity | topic | insight
updated: YYYY-MM-DD
---

# Заголовок

Содержимое с [[cross-references]] на другие страницы.
```

**Entity page** — про конкретный объект (человек, место, инструмент). Факты, контекст, история.
**Topic page** — синтез по теме. Растёт и усложняется. Содержит паттерны, выводы, ссылки на entities.
**Insight page** — дистиллированные паттерны. Обновляется редко, только когда паттерн подтверждён.

---

## Чего не делать

- Не переписывать историю — только дополнять
- Не создавать страницу ради страницы — только если реально нужна
- Не дублировать то что уже есть — ссылаться через `[[страница]]`
- Не хранить здесь raw данные — для этого есть Daily и Inbox
