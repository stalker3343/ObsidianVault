# Wiki Schema — инструкция для LLM

Это персональная вики об Артёме, построенная по паттерну Andrej Karpathy (llm-wiki.md).
Ты — LLM. Твоя работа: писать и поддерживать эту вики. Артём читает.

---

## Три слоя

**Raw Sources** (читаешь, никогда не меняешь):
- `Daily/*.md` — ежедневные логи
- `Inbox/*.md` — статьи, видео, посты
- Всё что Артём присылает в чат

**Wiki** (`System/Wiki/`) — твоя зона ответственности:
- Ты создаёшь страницы, обновляешь их, поддерживаешь cross-references
- Артём только читает

**Schema** — этот файл. Объясняет тебе как работать.

---

## Структура вики

```
System/Wiki/
  SCHEMA.md          ← этот файл, читай первым
  index.md           ← каталог всех страниц, читай при каждом разговоре
  log.md             ← append-only лог всех операций

  entities/          ← страница на каждый важный объект
    artyom.md        ← главная страница — профиль, ценности, контекст
    anya.md
    buddy.md
    [другие люди, места, инструменты по мере появления]

  topics/            ← синтез по темам, живёт и растёт
    health.md
    productivity.md
    work-career.md
    relationships.md
    learning.md
    wedding.md
    finance.md
    questions.md     ← открытые вопросы, которые требуют размышления/источников/решений
    [новые темы создавай сам по мере необходимости]

  insights/          ← дистиллированные паттерны и выводы
    patterns.md      ← стабильные поведенческие паттерны
    values.md        ← ценности и убеждения, как они эволюционируют
    decisions.md     ← принятые решения, правила и рабочие договорённости
  [другие разделы можешь добавлять по мере необходимости]
```

Разрешается менять структуру, если это релевантно информации.

**Правило создания новых страниц:** если концепция упоминается на 3+ страницах — заводи отдельную страницу и ставь cross-reference.

---

## Навигация

Читай в таком порядке:
1. `index.md` — чтобы понять что есть в вики
2. Релевантные страницы по теме разговора

Не надо читать всё сразу. `index.md` скажет тебе что читать.

---

## Операции

### Ingest (обновление из источника)
Триггер: "обнови вики", "запиши в вики", или конец дня.

1. Прочитай источник (Daily, присланный текст)
2. Определи затронутые страницы — entity + topic + insights
3. Обнови каждую: **не переписывай**, дополняй и уточняй
4. Если новое противоречит старому — замени с датой: `~~старое~~ → новое (2026-05-08)`
5. Проверь cross-references — добавь ссылки если нужно
6. Обнови `updated:` в frontmatter
7. Добавь запись в `log.md`: `## [YYYY-MM-DD] ingest | источник`
8. Один `git_atomic_commit` для всех файлов

Один источник может затронуть **5–15 страниц** — это нормально.

### Query (вопрос о себе)
1. Прочитай `index.md`
2. Прочитай релевантные страницы
3. Ответь с опорой на вики и называй страницы, на которые опираешься
4. Если ответ содержит ценный синтез — предложи сохранить его в вики
5. Если синтез сохраняется:
   - обнови релевантные страницы
   - при необходимости создай новую страницу
   - добавь запись в `log.md`: `## [YYYY-MM-DD] query | вопрос`

Хорошие ответы могут становиться частью вики так же, как новые источники. Это важно: ценные связи и выводы не должны исчезать в истории чата.

### Lint (раз в месяц по запросу)
Проверь:
- Противоречия между страницами
- Устаревшие утверждения (есть дата, прошло много времени)
- Страницы без входящих ссылок (orphans)
- Важные концепции без своей страницы
- Важные открытые вопросы без места в `topics/questions.md`
- Решения/правила, которые повторяются, но не записаны в `insights/decisions.md`
- Недостаток source/provenance у важных утверждений
- Пробелы — что стоит добавить

Добавь запись в `log.md`: `## [YYYY-MM-DD] lint | область проверки`.

## Provenance (связь с источниками)

Вики — слой синтеза, а не raw-архив. Но для важных утверждений нужно оставлять след к источникам.

Добавляй источники, когда утверждение:
- фиксирует устойчивый паттерн
- меняет или уточняет ценность/убеждение
- касается здоровья, финансов, отношений или работы
- может быть спорным или со временем устареть
- противоречит старым данным

Форматы:
- В тексте: `(источник: Daily 2026-05-04)`
- В конце секции: `Источники: [[01. Daily/2026-05-04]], [[01. Daily/2026-05-05]]`
- В `insights/patterns.md`: `Подтверждения: 2026-05-04, 2026-05-05`

Не нужно ставить источник к каждой мелочи. Ставь там, где будущей LLM важно понять, откуда взялся вывод.

## Открытые вопросы

Если источник или разговор содержит важный вопрос без ответа, сохрани его:
- на релевантной topic/entity/insight странице в секции `## Открытые вопросы`
- или в `topics/questions.md`, если вопрос сквозной

Формат:
```markdown
- [ ] Вопрос? Источник: `путь/дата`. Связано: [[страница]], [[страница]]
```

Вопросы нужны, чтобы вики не только хранила выводы, но и показывала направления будущего мышления.

---

## Решения и правила

Если в источниках или разговорах появляется устойчивое решение, правило или рабочая договорённость, сохраняй его в `insights/decisions.md`.

Примеры:
- вечерний план защищён как ритуал
- смотреть на результат/проблему, а не на процесс
- YouTube заменять на быстрый дофамин без инфошума

Формат:
```markdown
## Область

**Название решения**
Статус: active | experiment | retired
Суть: ...
Почему: ...
Источники: ...
Связано: [[...]]
```

## Index и Log

### `index.md`
`index.md` — content-oriented каталог. Обновляй при создании, переименовании или существенном изменении назначения страницы.

Минимум:
- ссылка на страницу
- краткое описание
- дата обновления

По мере роста можно добавлять:
- статус страницы: draft | active | stable
- количество источников
- последний источник
- ключевые связи

### `log.md`
`log.md` — chronological append-only запись операций. Каждая запись начинается с parseable-префикса:

```markdown
## [YYYY-MM-DD] ingest | Название источника
## [YYYY-MM-DD] query | Вопрос
## [YYYY-MM-DD] lint | Область проверки
## [YYYY-MM-DD] schema | Что изменилось
```

Шаблон ingest:
```markdown
## [YYYY-MM-DD] ingest | Название
Источники:
- `path`
Фокус:
- что брать / что игнорировать
Обновлено:
- [[page]]
Создано:
- [[page]]
Открытые вопросы:
- [ ] вопрос
```

Шаблон query:
```markdown
## [YYYY-MM-DD] query | Вопрос
Прочитано:
- [[page]]
Ответ сохранён: да/нет
Обновлено:
- [[page]]
Новые выводы:
- ...
```

Шаблон lint:
```markdown
## [YYYY-MM-DD] lint | Область проверки
Проверено:
- contradictions
- stale claims
- orphan pages
- missing pages
- missing provenance
Результат:
- ...
```

## Форматирование страниц

Каждая страница:
```markdown
---
wiki_page: [название]
type: entity | topic | insight
updated: YYYY-MM-DD
---

# Заголовок

Содержимое с [[cross-references]] на другие страницы.
```

**Entity page** — про конкретный объект (человек, место, инструмент). Факты, контекст, история.
**Topic page** — синтез по теме. Растёт и усложняется. Содержит паттерны, выводы, ссылки на entities.
**Insight page** — дистиллированные паттерны. Обновляется редко, только когда паттерн подтверждён.

---

## Чего не делать

- Не переписывать историю — только дополнять
- Не создавать страницу ради страницы — только если реально нужна
- Не дублировать то что уже есть — ссылаться через `[[страница]]`
- Не хранить здесь raw данные — для этого есть Daily и Inbox
