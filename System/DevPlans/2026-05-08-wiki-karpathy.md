# Dev Plan: Wiki Карпати — живая база знаний

> Источник паттерна: [llm-wiki.md by Andrej Karpathy](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)

## Суть паттерна

RAG — переоткрывает знания заново при каждом запросе. Никакого накопления.

Wiki Карпати — другое: **LLM инкрементально строит и поддерживает постоянную вики** — структурированные markdown-файлы между тобой и сырыми источниками. Каждый новый источник интегрируется в существующую вики: обновляются страницы, фиксируются противоречия, усиливается синтез.

Ключевая метафора: **Obsidian — IDE, я (бот) — программист, вики — кодовая база.**

Твоя работа: добавлять источники, задавать вопросы.  
Моя работа: писать и поддерживать вики — суммаризировать, перекрёстно ссылаться, обновлять.

---

## Три слоя

**1. Raw Sources** — сырые источники, неизменяемые.  
В нашем случае: Daily notes, Inbox (статьи, видео, посты), голосовые записи.  
Я читаю их, но не меняю.

**2. Wiki** — директория LLM-поддерживаемых markdown-файлов.  
`System/Wiki/` — я пишу и обновляю, ты читаешь и изучаешь.

**3. Schema** — документ, объясняющий мне как поддерживать вики.  
В нашем случае: раздел в `AGENT.md`. Описывает структуру, конвенции, воркфлоу инжеста.

## Структура `System/Wiki/`

```
System/Wiki/
  index.md       # каталог всех страниц с однострочным описанием + ссылками
  log.md         # хронологический append-only лог: что добавлено, когда, откуда

  # Страницы о человеке
  profile.md     # кто такой Артём: роль, цели, контекст
  health.md      # здоровье: симптомы, врачи, динамика
  habits.md      # паттерны поведения, что работает, что нет
  projects.md    # актуальный статус проектов
  people.md      # близкие: кто, отношения, контекст
  work.md        # работа, стек, поиск, цели
  learning.md    # английский, курсы, что изучает
  insights.md    # distilled инсайты из дейли и материалов
  preferences.md # предпочтения, антипатии, стиль
```

### index.md
Каталог всех страниц — ссылка + одна строка описания + дата обновления.  
Я читаю его первым при любом обращении к вики, чтобы найти релевантные страницы.

### log.md
Append-only лог. Каждая запись: что обработано и когда.  
Формат: `## [2026-05-08] ingest | Daily 2026-05-08` — парсится grep'ом.

---

## Операции

### Ingest
Ты: добавил новый источник (Daily, статья, пост).  
Я: читаю, обсуждаем ключевые идеи, обновляю 5–15 страниц вики, дописываю в log.md.

**Автоматический ежедневный ingest в конце дня** — крон в 22:00:
```
cc-connect cron add --cron "0 22 * * *" \
  --prompt "Прочитай дейли заметку за сегодня (Daily/YYYY-MM-DD.md) и обнови вики: извлеки инсайты, паттерны, обновления по здоровью/проектам/привычкам, обнови релевантные страницы System/Wiki/ и добавь запись в System/Wiki/log.md" \
  --desc "Daily wiki ingest"
```

Что я делаю при каждом запуске:
1. Читаю `Daily/{today}.md`
2. Определяю какие страницы вики затронуты
3. Обновляю 3–10 страниц (не переписываю, дополняю и уточняю)
4. Дописываю в `log.md`: `## [YYYY-MM-DD] ingest | Daily`
5. Коммичу всё одним git commit

### Query
Ты задаёшь вопрос о себе — я ищу релевантные страницы вики, читаю, синтезирую ответ.  
**Важно:** хорошие ответы-анализы тоже можно сохранять обратно в вики как новые страницы — так исследования накапливаются, а не пропадают в чате.

### Lint
Периодически (раз в месяц?) я прохожусь по вики и ищу:
- Противоречия между страницами
- Устаревшие утверждения
- Страницы-сироты без входящих ссылок
- Важные концепции без своей страницы
- Пробелы, которые стоит заполнить
