# Dev Plan: детерминированные команды и кнопки в боте

**Дата:** 2026-05-21
**Статус:** объединён → [[2026-05-22-bot-resilience-and-commands]]

---

## Задача

Добавить в Telegram-бота набор быстрых команд и/или inline-кнопок, которые выполняют действие детерминировано — без участия LLM в маршрутизации. Бот получает команду → сразу вызывает нужный skill, без размышлений.

## Контекст

Сейчас каждое сообщение проходит через LLM для определения типа. Это медленно и избыточно, когда пользователь точно знает, что хочет сделать. Пример: `/thought Купить хлеб` должен мгновенно уходить в `append_daily.py --kind thought` без промежуточного шага.

---

## Команды для реализации

| Команда | Действие |
|---|---|
| `/thought <текст>` | `append_daily.py --kind thought` |
| `/plan <текст>` | `append_daily.py --kind plan` |
| `/note <текст>` | `append_daily.py --kind material_note` |
| `/undo` | `undo_last.py` |
| `/status` | `status.py` |
| `/agenda` | singularity `get_agenda` → ответ в чат |
| `/task <текст>` | singularity `create_task` без проекта |

Опционально — inline-кнопки после каждого сохранения:
`[Отменить]` → вызывает `/undo` без подтверждения

---

## Шаги реализации

1. **Обработчик команд в cc-connect / входящем хуке**
   - Перехватывать сообщения начинающиеся с `/` до передачи в LLM
   - Парсить команду + аргументы
   - Напрямую вызывать соответствующий skill-скрипт или MCP

2. **Конфиг маппинга** `bot-commands.json` или секция в `AGENT.md`
   - `command → skill + args template`

3. **Bypass LLM** для зарегистрированных команд
   - Если команда в маппинге → выполнить, вернуть результат, не звать LLM

4. **Fallback** — незарегистрированные команды передаются LLM как обычно

5. **Регистрация команд в BotFather** (`setcommands`) для автодополнения в Telegram

---

## Затронутые файлы

- `cc-connect/config.toml` — возможно, хук на входящие
- `AGENT.md` — добавить строки маршрутизации для `/thought`, `/plan` и т.д.
- Новый файл: `bot-commands.json` или `skills/dispatch.py`

---

## Риски

- cc-connect может не поддерживать pre-LLM хуки — тогда обходной путь: первая строка `AGENT.md` с жёстким правилом «если сообщение начинается с `/thought` — немедленно вызвать skill»
- Конфликт с существующими `/undo_last`, `/status` (уже обрабатываются через LLM — нужно проверить, есть ли нативный хук)
