# Dev Plan: разблокировать curl и WebSearch

## Зачем это нужно

Сейчас бот не может самостоятельно читать внешние URL. Конкретный кейс который это обнажил: попытка прочитать gist Карпати для обновления dev plan — получили отказ.

Без этих инструментов бот не может:
- Читать статьи и gist по ссылке (нужно вставлять текст вручную)
- Читать документацию библиотек
- Получать актуальные данные (курсы, погода и т.п. в будущем)
- Проверять changelog инструментов (cc-connect и др.)

---

## Что именно заблокировано и почему

### WebSearch
Это встроенный инструмент Claude Code. Он не указан в `allowed_tools` в `config.toml` — поэтому в режиме `dontAsk` просто недоступен. Никакой специальной причины его блокировать нет, просто не был добавлен при настройке.

### curl через Bash
В `allowed_tools` перечислены только конкретные команды:
```toml
"Bash(/srv/.../skills/*.py *)",
"Bash(git -C /srv/ObsidianVault ...)",
"Bash(cc-connect cron *)"
```
Любой другой Bash-вызов, включая `curl`, заблокирован. Это правильная политика в целом — но `curl` для чтения публичных URL нужен.

## Изменения в config.toml

### 1. Добавить WebSearch в allowed_tools

```diff
 allowed_tools = [
   "Read",
   "Edit",
   "Write",
   "Grep",
   "Glob",
+  "WebSearch",
   "Bash(...)",
   ...
 ]
```

### 2. Добавить curl — только для чтения публичных URL

Ограничиваем паттерн: только GET, только https, без флагов записи/передачи данных:

```diff
+  "Bash(curl -fsSL https://*)",
+  "Bash(curl -fsS https://*)",
```

Что **не** разрешаем (и почему):
- `curl -X POST` — отправка данных наружу
- `curl --data` / `-d` — то же самое
- `curl -o /path` — запись файлов в произвольное место
- `curl http://*` — только https, не http

`/srv/telegram-obsidian-agent/cc-connect/config.toml`

Это конфиг cc-connect, не в git (`.gitignore`). Правится на сервере руками или через SSH.

Также обновить `config.toml.example` — задокументировать новые строки чтобы не забыть при следующей установке:

```diff
+  "WebSearch",
+  "Bash(curl -fsSL https://*)",
+  "Bash(curl -fsS https://*)",
```

---

## Почему это безопасно

- WebSearch — только поиск, не меняет ничего
- curl с паттерном `https://*` без `-X`/`-d` — только чтение публичных URL
- Бот не может отправить данные наружу через curl с этим паттерном
- Файловая система не затронута (нет `-o` в паттерне)

Основной риск: бот может читать любой публичный URL — это приемлемо для данного юзкейса.
