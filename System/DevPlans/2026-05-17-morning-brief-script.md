# Фича: скрипт утреннего брифа (morning_brief.py)

## Задача

Создать скрипт, который формирует один MD-файл `System/Today/morning-brief.md` с консолидированным контекстом для старта дня. Цель: агент читает **один файл** вместо 3–5 отдельных операций на старте разговора.

## Мотивация

Сейчас на старте агент делает:
1. `fetch_calendar.py` → читает `System/Today/schedule.md`
2. `singularity.dump_agenda_to_vault()` → читает `System/Today/singularity-tasks/YYYY-MM-DD.md`
3. Читает `System/Wiki/index.md`

Итого: 3 tool call только на инициализацию. С брифом: один `Read` — и весь контекст готов.

## Секции брифа (приоритет ↓)

| # | Секция | Источник | Статус |
|---|---|---|---|
| 1 | Дата, день недели | системное время | просто |
| 2 | Погода | wttr.in (JSON API, без ключа) | нужно добавить |
| 3 | Календарь на сегодня/завтра/послезавтра + ДР | `fetch_calendar.py` (переиспользовать) | есть |
| 4 | Задачи Singularity: просроченные + сегодня | Singularity API (переиспользовать `_get_agenda_data`) | есть |
| 5 | Выжимка вчера (Daily) | читать `Daily/YYYY-MM-DD.md`, брать секцию `## Capture` | нужно добавить |
| 6 | Выжимка позавчера | то же | нужно добавить |
| 7 | Последние 5 файлов Inbox | `os.listdir` + сортировка по mtime | нужно добавить |
| 8 | Открытые Dev Plans | `glob System/DevPlans/*.md`, фильтр `status: idea\|in-progress` | нужно добавить |
| 9 | Ключевые факты Wiki | читать `System/Wiki/entities/artyom.md` (первые N строк) | нужно добавить |
| 10 | Git status vault | `git status --short` | нужно добавить |

> **AGENT.md** — не включать: загружается хардкодом в контекст агентом-хостом.

## Архитектура

```
skills/morning_brief.py
  └─ собирает секции → пишет System/Today/morning-brief.md → git commit/push
```

Запуск:
- **По cron** в 05:55 МСК (`cc-connect cron add --cron "55 5 * * *" --exec "..."`)
- **На старте разговора** вместо текущих трёх вызовов — агент вызывает скрипт, читает один файл

Файл перезаписывается каждый день. Если вызван повторно в тот же день — обновляет (идемпотентно по дате).

## Погода

`wttr.in` отдаёт JSON без ключа:
```
GET https://wttr.in/Moscow?format=j1
```
Нужные поля: `current_condition[0]` → `temp_C`, `weatherDesc`, `humidity`, `windspeedKmph`.
Завтра: `weather[1]` → `hourly` → усреднить или взять пик.

## Выжимка Daily

Читать файл `Daily/YYYY-MM-DD.md`, извлекать секцию `## Capture` целиком (все bullet-пункты). Не суммаризировать — просто скопировать как есть: агент сам решит что важно.

## Шаги реализации

1. Создать `skills/morning_brief.py` — собирает все секции, пишет файл
2. Добавить погоду через `wttr.in` (httpx, уже есть в зависимостях MCP)
3. Добавить секцию выжимки Daily (вчера + позавчера)
4. Добавить секции Inbox, Dev Plans, Wiki snippet, git status
5. Добавить cron-задачу на 05:55 МСК
6. Обновить `AGENT.md`: на старте читать `System/Today/morning-brief.md` вместо трёх отдельных операций
7. Добавить `Bash(skills/morning_brief.py)` в allow в `.claude/settings.json`

## Риски

- **wttr.in** — внешний сервис, может быть недоступен. Секция погоды должна быть мягко опциональной (try/except → пропустить).
- **Большой файл** — если Daily вчера большой, бриф раздуется. Ограничить выжимку: первые 50 строк секции Capture или N символов.
- **Задержка старта** — если скрипт медленный (API Singularity + wttr.in + calendar), можно разбить на параллельные запросы через `asyncio.gather`.
