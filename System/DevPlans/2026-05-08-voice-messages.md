# Dev Plan: обработка голосовых сообщений

## Что известно

cc-connect умеет транскрибировать голосовые сообщения, но требует настройки:

```
🎙 Voice messages are not enabled. Please configure [speech] in config.toml.
```

Голосовые сообщения живут на стороне cc-connect — до меня (Claude) они дойдут уже как текст. Новый skill, скорее всего, не нужен.

---

## Шаг 1 — настроить [speech] в config.toml

Нужно выяснить точный формат секции. Запустить на сервере:

```sh
cc-connect --help
# или
cc-connect config --help
```

Скорее всего секция выглядит примерно так (на основе типичных STT-интеграций):

```toml
[speech]
provider = "openai"          # или "whisper-local", "google", etc.
api_key = "${OPENAI_API_KEY}"
model = "whisper-1"
language = "ru"              # подсказка языка — улучшает точность
```

После добавления секции — добавить переменную в `.env` если нужен новый ключ.

## Шаг 2 — как голос приходит ко мне после настройки

После транскрипции cc-connect передаёт текст как обычное сообщение. Возможно добавляет префикс типа `🎙` или метку `[voice]` — нужно протестировать.

Если никакого маркера нет → голосовые обрабатываются как текст, маршрутизация по AGENT.md работает как есть.

Если маркер есть → можно добавить в daily пометку `(голосом)` для понимания источника.

---

## Шаг 3 — опционально: пометка в daily

Если хочется видеть что запись пришла голосом:


Обсудить нужно ли это вообще — возможно лишнее.
